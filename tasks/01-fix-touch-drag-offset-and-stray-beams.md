# Task 01: Исправить touch-смещение при привязке к узлам и случайные балки после drag

- **Приоритет:** P0
- **Целевая метрика:** Снижение отвала `0–1m` (сейчас ~26%) и `1–2m` (сейчас ~26–27%), особенно на мобильном тач-трафике Poki.

## Проблема в коде

### 1. Конфликт `TOUCH_OFFSET_PX` с привязкой к узлам/якорям
В [`world/build_input.lua`](../world/build_input.lua) (`to_world_drag`, строки 59–62):
```lua
local function to_world_drag(sx, sy)
	local off = M.touch and tuning.TOUCH_OFFSET_PX * M.px_scale or 0
	return to_world(sx, sy + off)
end
```
В [`game/config/tuning.lua`](../game/config/tuning.lua): `TOUCH_OFFSET_PX = 42`, `TOUCH_TOLERANCE_TOUCH_PX = 48`.

Когда игрок на телефоне ставит палец на левый якорь `(0, 0)` (например, на уровне `1-1`) и тянет палец горизонтально прямо на правый якорь `(3, 0)`, `to_world_drag` поднимает цель на `42` виртуальных пикселя вверх:
- На стандартной ширине/высоте камеры уровня `1-1` (`area = { -1, -3, 4, 4 }`) `42px` составляют `~1.1–1.3 м`.
- Это находится на самой границе `tol_world()` (`48px`). Стоит пальцу сместиться на 5–6 px выше или экрану иметь чуть больший масштаб — прицел перестаёт магнититься к якорю `(3, 0)` и привязывается к точке сетки `(3, 1)` (`sqrt(3^2 + 1^2) = 3.162 <= 3.165`).
- В итоге новичок строит диагональную дорогу *в воздух* над берегом, нажимает `ПУСК!` и падает в воду.

### 2. Построение лишних балок после завершения `drag_beam`
В [`world/build_input.lua`](../world/build_input.lua):
- `build_preview()` (строка 128) после отпускания пальца оставляет конечный узел выделенным: `session.selected_node = n.id`.
- При следующем нажатии на пустое место (`press`, строки 162–163): `elseif selected() then st.mode = "place_press" end`.
- Если пользователь просто тапнул по пустому месту, чтобы снять выделение (как ожидается на ПК и таче), `release()` (строки 230–238) **строит новую случайную балку** в сторону тапа (даже если тап далеко — `snap.beam_target` обрежет её до `max_len`!).

## Что нужно сделать

1. **Умный приоритет магнитного захвата узлов в `world/build_input.lua` / `game/bridge/snap.lua`:**
   - В `target_from(from, sx, sy, drag)` при `drag == true` сначала проверять `find_node` по **сырым** мировым координатам пальца `to_world(sx, sy)` (где сам палец целится в видимый красный якорь или существующий узел), и только если под пальцем нет доступного узла — применять `to_world_drag(sx, sy)` с `TOUCH_OFFSET_PX` для прицеливания по пустой сетке.
   - Убедиться, что при наличии существующего узла в пределах `tol_world()` приоритет отдаётся `anchor` / уже построенным узлам, а не пустой клетке сетки над ними.
2. **Разделить режимы `drag-build` и `tap-tap chain` в `world/build_input.lua`:**
   - После завершения `drag_beam` (`release` строки 204–211) **не оставлять** `session.selected_node` активным (или сбрасывать `selected_node = nil` после drag, оставляя автовыделение только для осознанного `tap-tap` режима через `node_press`).
   - В `place_press` (тап при выбранном узле): если точка тапа находится дальше `max_len + tol_world()` от `selected_node` (игрок тапнул в другую часть экрана или по пустому фону для сброса), снимать выделение вместо построения обрезанной балки.

## Критерии приёмки

- [ ] На тач-устройстве горизонтальный драг от `(0, 0)` ровно до `(3, 0)` на уровне `1-1` стабильно привязывается к `(3, 0)` (даже с погрешностью по Y ±20 px).
- [ ] После завершения drag-протяжки тап по пустому месту не строит случайную балку.
- [ ] `tap-tap` цепочка (тап по узлу -> тап в соседнюю клетку) продолжает работать и покрыта тестом в [`tests/test_runtime.lua`](../tests/test_runtime.lua).
- [ ] Добавлен тест в `tests/test_runtime.lua` для `touch` режима (`build_input.touch = true`) на горизонтальный drag от `(0, 0)` к `(3, 0)`.
